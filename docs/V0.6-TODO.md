This was `V0.5-TODO.md` until 0.5.0 shipped the operator surface, and

The three items came from reading

and [LoopX](https://blog.mushroom.cv/blog/loopx-loop-engineering-state-kernel-long-running-agents/)

## Shipped in 0.5.0

- [x] **Re-arm a running service after a resume.** A halted loop no longer
  disposes its timer: each tick peeks at STATE without the lock and writes
  nothing until the revision moves, so an answer or a resume — from the CLI or
  the dashboard — is picked up on the next tick with no profile restart.
- [x] **An operator can pause a healthy loop.** `devloop pause`, and the same
  from the dashboard ([Dashboard.md](./Dashboard.md)).
- [x] **An operator surface.** A page at `/devloop/` behind DSH's own login,
  reachable over the tailnet: every project's loop, its tasks and questions,
  answer / resume / pause, and registering and starting projects, each with its
  own loop under a shared daily cap ([Dashboard.md](./Dashboard.md)).

## Shipped in 0.4.2

- [x] **The gate prints commands that resolve.** It used to print
  `devloop answer retry`, the one line an operator could not paste, because
  nothing puts `devloop` on `PATH`. Of the three candidate fixes — an absolute
  path, a documented alias, a launcher on `PATH` — it now prints the absolute
  invocation of the copy that was run, plus the project root, and a test feeds
  every printed line back to the CLI
  ([#29](https://github.com/jhfnetboy/DevLoop/pull/29)). A launcher on `PATH`
  is still the nicer spelling; it is no longer needed for correctness.

## Shipped in 0.4.1

- [x] **Gates.** A halt now poses a concrete question with the answers the loop
  can act on, and `devloop answer` applies one. The remaining half is that the
  loop still stops rather than waiting on the gate — tracked below as re-arming
  a running service.
- [x] **Host-run acceptance.** Operator-configured commands now run in the task
  worktree before review. The model's `acceptance` text stays advisory; a model
  never chooses what the host executes.
- [x] **Charge quota for work that happened.** A dispatch refused before any
  provider saw it is refunded; one that reached a model and failed still costs an
  attempt. Charging only after a verified result was rejected: a backend that
  never returns would then retry for ever.

## Deferred, with reasons

- [ ] **Validate the shape of `acknowledged` on load.** `isLoopState` checks
  every other field and skips this one, so a hand-edited or truncated record
  loads unchecked. Deferred because nothing branches on it — it is what an
  operator declined and when — and because the only way `isLoopState` can reject
  something is an integrity hold, which is the one halt no answer can lift.
  Spending that on a field no code reads is a bad trade; a narrow shape check
  that degrades to dropping the field would be the fix.

- [ ] **The window between charging an attempt and refunding it.** The charge is
  written inside the tick lock, the refund takes the lock again after the
  dispatch returns; a process that dies in between keeps a charge that is never
  handed back on restart. Bounded at one attempt per crash and visible in
  `EVENTS.jsonl`, so it is a documented cost rather than a silent one. Closing it
  means charging after the result instead, which is a larger change to the tick's
  single-writer shape than the refund was.

- [ ] **Task claims and leases.** LoopX gives todos an owner and a lease.
  Deferred because there is no consumer: the service runs one dispatch at a time
  behind a `busy` flag, so a lease would be machinery for a parallelism that does
  not exist yet. Revisit with parallel workers.
- [ ] **Usage reporting from dsh.** `dsh --profile headless` has no output
  options, so T1/T2 spend is invisible to the cost cap — the tier that spends the
  most. Needs either an upstream change to dsh or an API path for those tiers.
  Two assertions currently fail the day this changes, which is the reminder.
- [ ] **Re-read a verdict before merging.** A pull-request approval that is
  withdrawn or edited after it was recorded is not re-checked at merge time. The
  recorded verdict is an attestation about a commit, which is defensible, but the
  alternative is worth revisiting if reviewers start editing.
- [ ] **Consume GitHub review submissions.** Only issue comments are read.
  Missing an approval merely makes the loop wait; missing a *Request changes*
  means an objection never arrives, and that is the natural place to raise one.
- [ ] **Record which principal approved.** `RoutedBackend` overwrites an
  adapter's self-reported identity by design, so `STATE.json` names the route
  rather than the reviewer. The pull request holds the audit trail.
- [ ] **A durable hold when the lock is contended.** `persistBackendFailure`
  ignores a failed `persistAgentHold`; the loop then wedges to a generic
  no-progress halt instead of a specific one. Pre-existing, and the forge's
  long dispatch makes it more visible.
