# 开 PR 前的自审深度（pre-PR review）

**这份文档只回答一个问题:这次改动,在开 PR 之前,必须自审几轮。**

「怎么自审」在 [`pr-quality.md`](pr-quality.md);「拿到评审回执之后怎么办」在
[`review-triage.md`](review-triage.md)。这里只定深度,以及深度**由谁说了算**。

## 深度不是作者自己定的

自审深度**必须机械导出,不能自我申报**。原因很直接:一个正准备跳过审查的模型,
恰恰就是那个会把自己的改动评成「就改了点文档」的模型。

本仓库的真实案例:一个同时动了 `.github/workflows` 和两个 CI 执行脚本的 PR,
被作者自评为 D 级;评审者把它升到 A,查出 6 个真实缺陷,其中两个能抹掉线上站点。

所以定级交给 `scripts/grade-change.sh`——它只看**改了哪些路径**和**改了多少行**,
作者没法跟它辩论。

```
bash <skill>/scripts/grade-change.sh [--base <集成分支>]
```

输出稳定可解析:

```
GRADE=<A|B|C|D>
REASON=<定成这级的依据>
ROUNDS=<需要的对抗轮数>
FILES=<n> LINES=<n>
```

`grade-change.sh` **只报告,不拦截**(除用法错误外恒 exit 0)。拦截由 `git-guard.sh pr-create` 做。

## 分级 → 轮数

| 级 | 什么样的改动 | 对抗轮数 |
|:---|:---|:---|
| **A** | 涉钱/资产 · 安全/密钥 · 数据删除或迁移 · **任何被自动化消费的文件**(CI workflow、守卫/门禁脚本、构建与部署脚本、git hook、依赖清单) | **3** |
| **B** | 净改动 >100 行,或横跨 ≥3 个顶层目录 | **3** |
| **C** | 含可执行代码,但够不上 A/B | **1** |
| **D** | 纯文档(`.md` / `.txt` / `.rst`,别的什么都没有) | **1** |

**取最高命中**:只要有一个 A 类路径,整次改动就是 A。

两条容易被低估的判定,是刻意这么设计的:

- **「被自动化消费」是 A 的核心判据。** 这些文件不由人执行,坏了是**静默地**坏——
  一个错的守卫比没有守卫更糟。
- **`.yml` / `.json` / `.sh` 不算文档**,哪怕它读起来像配置——因为有东西会执行它。只有散文算 D。

## 一轮「对抗」是什么

一轮 = **换一个视角**把 diff 当成有问题的东西去查,而不是「看看还行」。
具体清单见 [`pr-quality.md`](pr-quality.md) §2。要点:

- 每一轮**换一个 lens**(正确性 / 安全 / 生产失败模式 / 边界与并发),
  三轮同一个视角等于一轮做了三遍;
- 优先用**独立上下文**(子 agent 或 Codex),而不是在写代码的同一段上下文里自我复查;
- 每轮发现的阻塞项 → 修 → **重跑自测** → 再进下一轮。不阻塞的记进
  [`followup-ledger.md`](followup-ledger.md)。

A/B 级的 3 轮是**下限**,不是配额:三轮跑完仍在冒新的阻塞项,就继续。

## 和门禁的关系

`preflight.sh run` 跑完本仓库自己的检查后,会把算出来的 grade 写进戳记
(`.git/pilot-preflight` 的 `grade=` 行)。`git-guard.sh pr-create` 在放行前:

1. 要求戳记**存在且绑定当前 HEAD**——没跑过检查、或检查跑的是别的 commit,直接拒绝;
2. A/B 级会打印一行提醒,指回这份文档要求的 3 轮。

**门禁只能验证「检查跑过了」,验证不了「你真的对抗审了 3 轮」。**
那一步没有机械证据,只能靠你自己诚实执行——这也正是它写在这里、而不是只写在脚本注释里的原因。

紧急情况的逃生口是 `PILOT_SKIP_PREFLIGHT=1`,它会往 stderr 打一行显式警告。
**用了就要在 PR body 里说明为什么**;没人看得见的绕过,和没有检查是一回事。
